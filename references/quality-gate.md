# 质量闸门

## 硬闸门 H1—H6

| 编号 | 闸门 | 失败条件 |
|---|---|---|
| H1 | 保护项完整 | 法规标准、数字日期、技术参数、责任主体、正式结论缺失或被改写 |
| H2 | 证据状态合规 | 高风险主张无来源、与来源矛盾，或把待确认项写成既定事实 |
| H3 | 规范强度一致 | “应、须、不得、可、负责、承担”等语义强度发生变化 |
| H4 | 场景合同符合 | 文种、默认 `scope`、输出格式或禁区与对应场景包冲突 |
| H5 | 用户授权不越界 | 超出指定段落、改写档位或任务类型，擅自扩写、删改或重构 |
| H6 | 结论可追溯 | 关键判断无法对应输入事实、明确来源或“待确认”标记 |

任一硬闸门失败，结果不得标记为“通过”。先恢复原文或降级为诊断、待确认清单。

## 软指标

- T1 表演性/模板化短语是否得到处理。
- T2 密集路标词、机械排比和固定句式是否降到合理水平。
- T3 高频抽象词是否因缺少对象和动作而空泛。
- 句长是否有自然变化，同时保持正式度。
- 每段是否有信息增量，章节结尾是否提供决策信息。
- 对象、动作、条件、边界、责任和验证方式是否足以支撑当前文种。

软指标用于改进，不用于判断作者身份，也不能凌驾于 H1—H6。

## 判定优先级

1. 先判 H1—H6；任何一项失败即整体失败。
2. 硬闸门全部通过后，再汇总 T1/T2/T3 和结构性软指标。
3. 软指标命中不等于必须改；制度条款、标准引用、响应表和技术清单可保留必要重复。
4. 证据不足时，宁可输出“待确认”，不以语言完整性掩盖事实缺口。

## 两遍复读

### 第一遍：保真复读

逐项核对法规标准、数字日期、参数、组织岗位、责任关系、规范性用语和正式结论。必要时运行 `protected_diff.py` 与 `evidence_check.py`。

### 第二遍：成文复读

以目标读者视角检查场景语域、信息顺序、段落作用、信息增量、T1/T2/T3 和输出合同。必要时运行 `style_audit.py`。第二遍不得破坏第一遍已确认的保护项。

## 默认质量报告模板

```text
质量结论：通过 / 不通过 / 待确认后通过

硬闸门：
- H1：通过/失败——依据
- H2：通过/失败——依据
- H3：通过/失败——依据
- H4：通过/失败——依据
- H5：通过/失败——依据
- H6：通过/失败——依据

软指标：
- T1/T2/T3：命中项与处理情况
- 结构：信息增量、责任、结论

待确认项：
- 事实或来源｜风险等级｜建议动作
```

若用户只要求成稿且全部硬闸门通过，默认不附长篇审计过程；只在存在风险或用户要求时附质量报告。
