# 基础层确定性合成证据基准

## 目的

Foundation 12 为维护者提供一个统一的确定性合成证据基准。基准通过既有公开 CLI 接缝验证基础层集成行为，不新增平行的运行时决策入口，也不改变三个审计脚本的接口或退出码。

基准清单位于 `evals/foundation-synthetic-benchmark.json`，统一测试入口为：

```bash
python3 -m unittest tests.test_foundation_synthetic_benchmark -v
```

## 证据属性

基准元数据固定声明：

- `evidence_type: deterministic-synthetic-fixture`；
- `model_execution: false`；
- `real_engineering_evidence: false`；
- 输入为确定性合成数据，属于非真实工程证据；
- 只允许形成识别覆盖和基础支持声明。

基准通过只表示当前代码对公开数据合同和冻结预期保持一致。它不构成深度支持，不构成联审支持，不构成前向验证，也不证明统计稳定性；不能替代正式要求、脱敏真实正例、失败例、生命周期边界案例、全新上下文运行或人工审稿。

## 覆盖矩阵

| 分组 | 统一验证内容 | 公开接缝 |
|---|---|---|
| 身份与路由 | 三个业务域、七类文种场景、生命周期近失配、复合材料 | `scripts/perception_decision.py` |
| 效力与处理 | 陈述效力不强化/不弱化、`quick_path`、`two_stage` | `scripts/perception_decision.py` |
| 材料与结构 | 七类材料关系、七类冲突阻断、正式模板适配、提取缺口阻断 | `scripts/perception_decision.py` |
| 项目上下文 | 用户确认更新、上游变化待复核、项目隔离 | `scripts/project_context.py` |
| 数据边界 | 禁止持久化占位输入被拒绝，错误不回显且不写盘 | `scripts/project_context.py` |
| 稳定回归 | 复用既有评测、触发、审计与稳定行为测试模块，并核对 43 项行为评测、20 项触发边界及 `v1.1.0` 版本 | 既有测试与 CLI |

身份与集成案例引用已有确定性夹具，避免复制并逐渐分叉的第二套业务输入。基准文件保存独立的预期分类、处理模式和阻断结果；测试只从公开 CLI 的 JSON 输出观察行为，不断言私有函数或内部扫描顺序。稳定回归会直接运行既有评测不变性、触发准确率、审计行为和稳定基础合同测试，条目数量只作为附加的结构检查。

## 数据边界

基准文件不保存真实项目材料、项目受限事实、个人信息或凭据。禁止持久化用例只登记无秘密的输入档案标识；测试运行时临时构造合成的敏感格式占位值，并在临时目录中验证拒绝、脱敏和不写盘，完成后由临时目录自动清理。

项目上下文用例只使用 `SYNTHETIC-PROJECT-*` 标识和合成材料关系。基准不调用外部网络、上传服务或外部数据库。

## 维护规则

1. 新增用例时必须保持 `case_id` 唯一，并同步更新 `case_count`。
2. 新增输入必须保留确定性合成、未执行模型和非真实工程证据声明。
3. 不得把 `deep_support`、`joint_review_support`、`forward_validation` 或 `statistical_stability` 写入通过结果。
4. 公开决策出现新增支持级别前，必须先满足材料合同证据门槛，不能以基准用例数量代替证据质量。
5. 运行统一基准后仍须执行完整测试、JSON 解析、Skill 校验、链接、版本、依赖、缓存、隐私及独立稳定版目录检查。
