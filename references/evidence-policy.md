# 证据策略

`CONTRADICTED` 建议记录 `conflict_ref`，`OPINION` 建议记录 `owner`；缺少这些可选字段只产生警告，不改变原有阻断语义。脚本增加状态统计，但不自动判断 Claim 真伪。

## 目的

文字可以调整，客观事实必须可追溯。证据策略用于区分事实、判断和待确认内容，防止模型把建议写成事实、把无来源数字写成测算结果。

证据状态只描述可追溯性，不表示陈述在管理链条中的效力。假设、专业判断、建议方案、已批复边界、合同承诺、实施事实和验收结论按[陈述效力策略](statement-force-policy.md)独立记录；`SUPPORTED` 不会自动强化原效力。

## 何时建立 Claim

以下内容进入证据视图：

- 数字、比例、金额、日期、性能指标和效果预测；
- 事故、事件、案例、用户反馈和项目业绩；
- 法律、政策、标准适用性及监管要求；
- “最佳、领先、普遍认为、研究表明”等权威性或比较性判断；
- 产品能力、认证、检测报告、客户案例和履约承诺；
- 可能影响投资决策、招标评分、验收结论或责任划分的陈述。

普通语言调整、明确标注的方案建议和不涉及事实的结构意见不必逐句建 Claim。

## 状态

| 状态 | 含义 | 动作 |
|---|---|---|
| `SUPPORTED` | 输入材料或明确来源可直接支持 | 保留，并记录 `source_ref` |
| `OPINION` | 明确属于判断、建议或方案选择 | 保留判断属性，不伪装为事实 |
| `UNSUPPORTED` | 客观陈述缺少来源 | 高风险阻断；中低风险警告 |
| `CONTRADICTED` | 与输入事实或另一可靠来源冲突 | 阻断定稿 |
| `NEEDS_USER_CONFIRMATION` | 必须由用户确认才能确定 | 阻断定稿并列出待确认项 |

## 风险等级

- `high`：合同承诺、招标响应、投资效益、验收结论、法规适用、关键参数和责任事项。
- `medium`：一般项目现状、趋势判断、方案比较和内部管理描述。
- `low`：不影响决策或责任的背景性描述。

## 证据账本格式

```json
{
  "claims": [
    {
      "claim_id": "C-001",
      "claim": "平台应支持两地三中心部署",
      "status": "SUPPORTED",
      "risk": "high",
      "source_ref": "技术需求书4.2.3"
    }
  ]
}
```

## 写作规则

- 不为 `UNSUPPORTED` Claim 编造机构、报告、年份、样本或测算过程。
- 可以删除无源权威外壳，但不得把依赖该权威才能成立的判断伪装成普通事实。
- 用户要求保留论证位置时，明确写出“来源待补”或“数据待确认”。
- `OPINION` 使用“建议、经比较、本方案推荐”等责任清晰的判断表达。
- 最终稿存在 blocker 时，不得声称“可定稿、可签批、完全响应或通过验收”。

## 因果外推与计划状态

计划偏差必须绑定同一对象、该对象自身的计划基线和可比较的材料时点。输入直接确认某对象已延期，或同时给出该对象截止日期、材料时点和仍未完成状态时，才可写成“已延期、已滞后、已逾期”。

上游事项延期、依赖关系或下游事项尚未完成，只能支持“可能影响下游节点、存在进度风险”等风险判断，不能跨对象转写为“下游事项已延期”。输入明确“A 延期导致 B 尚未完成”时，可以保留因果关系，但“尚未完成”不等于“已延期”。

## 确定性复核

```bash
python3 scripts/evidence_check.py evidence-ledger.json
```

退出码 `0` 表示通过，`1` 表示账本格式错误，`2` 表示存在阻断项。脚本只验证账本状态，不自动识别正文中的全部事实。
